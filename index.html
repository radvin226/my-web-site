یک SDK که ساخت ربات روی CodeMeet را همان‌قدر ساده می‌کند که باید باشد.

Radvin یک فریم‌ورک پایتونی و کاملاً async است، با همان تجربهٔ آشنای python-telegram-bot، برای اینکه دیگر لازم نباشد مستقیم با API خام CodeMeet دست‌وپنجه نرم کنید. Handler بنویسید، فیلتر ترکیب کنید، و بقیه‌اش با Radvin.

شروع نصب دیدن مثال کامل
main.py — python3
/start
Hello Radvin

نصب

Radvin روی PyPI منتشر شده و با هر ابزار مدیریت پکیج پایتون نصب می‌شود.

bash
# نصب پایه
pip install radvin

# اکستنشن‌های اختیاری
pip install "radvin[redis]"            # RedisPersistence
pip install "radvin[webhook-fastapi]"  # اجرای run_webhook با FastAPI
pip install "radvin[webhook-flask]"    # اجرای run_webhook با Flask

نیازمندی: پایتون ۳٫۱۱ یا بالاتر. Radvin از قابلیت‌های تایپ مدرن پایتون (مثل X | None) استفاده می‌کند.

۰۲ / شروع

شروع سریع

یک ربات کامل با دستور /start و پاسخ به پیام متنی، در کمتر از ۲۰ خط:

main.py
from radvin import Application, CommandHandler, MessageHandler, filters


async def start(update, context):
    await update.message.reply_text("Hello Radvin")


async def echo(update, context):
    await update.message.reply_text(update.message.text)


app = (
    Application
    .builder()
    .token("TOKEN")
    .build()
)

app.add_handler(CommandHandler("start", start))
app.add_handler(MessageHandler(filters.TEXT, echo))

app.run_polling()

همین. run_polling() کل چرخهٔ حیات را مدیریت می‌کند: مقداردهی اولیه، حلقهٔ دریافت آپدیت، و خاموشی تمیز با Ctrl+C.

۰۳ / هستهٔ فریم‌ورک

Application و Builder

Application شیء مرکزی است: نگه‌دارندهٔ Bot، Dispatcher، JobQueue و Persistence. آن را با الگوی fluent builder می‌سازید: 

app = (
    Application
    .builder()
    .token("TOKEN")
    .persistence(RedisPersistence("redis://localhost:6379/0"))
    .request_timeout(45)
    .build()
)

چرخهٔ حیات

متدوظیفه
initialize()باز کردن session شبکه و بارگذاری persistence
start()روشن کردن job queue
stop()توقف polling/webhook و ذخیرهٔ persistence
shutdown()بستن کامل session شبکه

run_polling() و run_webhook() هر چهار مرحله را خودکار و به‌ترتیب صدا می‌زنند؛ نیازی به فراخوانی دستی‌شان نیست مگر بخواهید Application را داخل برنامهٔ async خودتان جا بدهید.

۰۴ / هستهٔ فریم‌ورک

Bot API Client

کلاس Bot یک کلاینت واقعی و کامل روی aiohttp است: retry با backoff، timeout جداگانه برای اتصال/کل درخواست، و تبدیل خطاهای HTTP به exception های مشخص.

متدکاربرد
get_updates()دریافت آپدیت‌ها (long polling)
send_message()ارسال پیام متنی، با پشتیبانی از کیبورد inline
edit_message_text()ویرایش متن یک پیام ارسال‌شده
delete_message()حذف یک پیام
answer_callback_query()پاسخ به کلیک روی دکمهٔ شیشه‌ای
set_webhook() / delete_webhook()ثبت یا حذف آدرس webhook

در عمل بیشتر این متدها را مستقیم صدا نمی‌زنید — به‌جایش از متدهای راحتی روی خود آبجکت‌ها استفاده می‌کنید، مثل update.message.reply_text()، که پشت صحنه همین کلاینت را فراخوانی می‌کند.

خطاها: Unauthorized، BadRequest، TimedOut و NetworkError همگی از RadvinError ارث می‌برند، پس می‌توانید همه را با یک except RadvinError بگیرید یا هرکدام را جدا مدیریت کنید.

۰۵ / هستهٔ فریم‌ورک

Dispatcher

هر آپدیت ورودی از میدل‌ور رد می‌شود، بعد بین گروه‌های handler می‌گردد. داخل هر گروه، اولین handler منطبق (به ترتیب priority) اجرا می‌شود و بقیهٔ همان گروه را متوقف می‌کند؛ گروه‌های دیگر همچنان اجرا می‌شوند.

app.add_handler(CommandHandler("start", start), group=0)
app.add_handler(LoggingHandler(), group=1)  # همیشه اجرا می‌شود، مستقل از گروه ۰

مدیریت خطا هم همینجا اتفاق می‌افتد: هر استثنایی که از یک callback بیرون بزند به تمام error handler های ثبت‌شده با add_error_handler() می‌رسد.

۰۶ / مدیریت آپدیت‌ها

Handler ها

CommandHandler

تطبیق با دستورهای /command، با استخراج خودکار آرگومان‌ها در context.args.

MessageHandler

تطبیق با هر پیامی که از فیلتر داده‌شده رد شود، مثل filters.TEXT.

CallbackQueryHandler

تطبیق با کلیک روی دکمهٔ شیشه‌ای؛ می‌توان با pattern فقط داده‌ٔ خاصی را گرفت.

ConversationHandler

ماشین‌حالت چندمرحله‌ای برای فرم‌ها و گفت‌وگوهای گام‌به‌گام.

مثال ترکیبی
app.add_handler(CommandHandler("greet", greet))
app.add_handler(MessageHandler(filters.TEXT, echo))
app.add_handler(CallbackQueryHandler(on_click, pattern=r"^page:\d+$"))
۰۷ / مدیریت آپدیت‌ها

Filter ها

فیلترها ترکیب‌پذیرند — دقیقاً مثل عبارات بولی — تا بدون شرط نوشتن داخل callback، منطق تطبیق را بیان کنید.

فیلترتطبیق با
filters.TEXTهر پیام متنی که با اسلش شروع نشود
filters.COMMANDپیام‌هایی که با / شروع می‌شوند
filters.Regex(pattern)متنی که با یک الگوی regex مطابقت دارد
filters.User(ids=…, usernames=…)پیام از کاربر یا کاربران مشخص
filters.Chat(ids=…, type=…)پیام از چت یا نوع چت مشخص
 
filters.TEXT & filters.User(ids=12345)
filters.TEXT | filters.COMMAND
~filters.TEXT
۰۸ / مدیریت آپدیت‌ها

ConversationHandler

برای فرم‌های چندمرحله‌ای (مثلاً ثبت‌نام: نام → سن → پایان)، هر state لیستی از handler دارد و هر callback با برگرداندن state بعدی، مسیر گفت‌وگو را مشخص می‌کند.

NAME, AGE = range(2)

conv = ConversationHandler(
    entry_points=[CommandHandler("register", ask_name)],
    states={
        NAME: [MessageHandler(filters.TEXT, ask_age)],
        AGE:  [MessageHandler(filters.TEXT, finish)],
    },
    fallbacks=[CommandHandler("cancel", cancel)],
)
app.add_handler(conv)

برگرداندن END از هر callback، گفت‌وگو را برای همان کاربر/چت پاک می‌کند.

۰۹ / پیام و رابط کاربری

دکمه‌های شیشه‌ای (Inline Keyboard)

keyboard = InlineKeyboardMarkup([
    [InlineKeyboardButton("کلیک کن", callback_data="button1")]
])
await update.message.reply_text("یک گزینه را انتخاب کن:", reply_markup=keyboard)

نکتهٔ مهم: CodeMeet فقط در حالت webhook رویداد کلیک روی دکمه‌های شیشه‌ای (callback_query) را ارسال می‌کند. اگر با run_polling() اجرا کنید، این دکمه‌ها نمایش داده می‌شوند اما پاسخی برنمی‌گردد.

۱۰ / پیام و رابط کاربری

Context

CallbackContext دومین آرگومانی است که هر callback می‌گیرد و دسترسی به سه فضای ذخیره‌سازی مستقل را فراهم می‌کند:

ویژگیمحدوده
context.user_dataمخصوص همان کاربر، در همهٔ چت‌ها
context.chat_dataمخصوص همان چت، مستقل از کاربر
context.bot_dataسراسری، مشترک بین همهٔ کاربران و چت‌ها
۱۱ / وضعیت و زیرساخت

Persistence

دو پیاده‌سازی آماده وجود دارد و هر دوی آن‌ها همان دیکشنری‌های سریع در حافظه را در اختیار handler ها می‌گذارند:

MemoryPersistence

فقط در حافظهٔ پردازش؛ با ری‌استارت از بین می‌رود. مناسب توسعه و تست.

RedisPersistence

روی redis.asyncio؛ وضعیت بین ری‌استارت‌ها و چند worker باقی می‌ماند.

app = (
    Application.builder()
    .token("TOKEN")
    .persistence(RedisPersistence("redis://localhost:6379/0"))
    .build()
)
۱۲ / وضعیت و زیرساخت

Middleware

هر میدل‌ور دو قلاب دارد. برگرداندن False از before_update آپدیت را کلاً متوقف می‌کند و اجازه نمی‌دهد به هیچ handler برسد.

class AuthMiddleware(BaseMiddleware):
    def __init__(self, allowed_user_ids):
        self.allowed_user_ids = allowed_user_ids

    async def before_update(self, update, context):
        user = update.effective_user
        return user is None or user.id in self.allowed_user_ids

app.add_middleware(AuthMiddleware({111, 222}))

Job Queue

زمان‌بند داخلی بر پایهٔ asyncio، برای کارهایی که باید بعداً یا به‌صورت دوره‌ای اجرا شوند — بدون نیاز به Celery یا ابزار جدا.

app.job_queue.run_once(send_reminder, when=60)
app.job_queue.run_repeating(check_status, interval=300, first=10)

Plugin ها

هر plugin فقط یک تابع setup(application) نیاز دارد. Radvin آن را کشف و بارگذاری می‌کند:

def setup(application):
    application.add_handler(CommandHandler("ping", ping))

app.plugin_loader.load("my_plugin_package.ping")
